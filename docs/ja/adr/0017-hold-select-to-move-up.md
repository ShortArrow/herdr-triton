# 0017. Select の長押しでハイライトを上へ動かす

[English](../../adr/0017-hold-select-to-move-up.md) | 日本語

- Status: Accepted
- Base: [`24bf396`](https://github.com/ShortArrow/herdr-triton/commit/24bf3960d30efa2dbd5ecfbbf06b497513417af6)

## Context

Select はハイライトを下へ動かすだけだった。
1回押しすぎると、リストを一周して戻るまで押し続けるしかなく、Claude Code の質問プロンプトでは「Type something.」と「Chat about this」も通ることになった。
Select は `Down` で動いていたので、長押しと分かった時点ではハイライトはもう動いたあとだった。

ADR 0015 では、フォーカスとウィンドウを前面に出すことは一緒に起きてよいので、Jump は `Down` で動かしたまま長押しを重ねた。
下へ動かすことと上へ動かすことはそうはいかない。`down` のあとに長押しで `up` を送ると、ハイライトは2回動いて1つ上で止まることになる。

## Decision

- 長押しはオプションとし、`config.toml` の `select_hold` で選ぶ。既定の `"none"` では Select はこれまでどおり `Down` で動く。`"up"` で以下が有効になる
- Select は、押していた時間が 500 ms 未満なら `Up` で動き、これまでどおりハイライトを動かす
- Select が 500 ms 押されたままなら、代わりにエージェントの戻りキーを1回送り、その押下では離したときも含めてそれ以上何もしない
- 長押しの判断は押下と同じにする。再取得し、`approvable(focused)` か `lapsed_focus(focused)` を必要とし、lapsed の pane では画面にハイライト付きの番号リストを必要とする
- 組み込みのエージェントすべてで長押しが効くように、Codex にも戻りキー `["up"]` を与える

## Consequences

- オプションを付けなければ何も変わらない。下の遅れは、長押しを選んだ人だけが負う
- 短い Select は、キーが上がったときにハイライトを動かす。これまでより 0.1〜0.2 秒ほど遅れる
- 1番目の選択肢でも長押しは戻りキーを送る。リストがそこで止まるか回るかはエージェント次第
- Select の点滅は、短押しでは離したあとに、長押しでは 500 ms の時点で出る

## Alternatives

- **`Down` で `down` を送り、長押しで取り消す**: ハイライトが下へ動いてから2つ上へ動くのが見え、lapsed の pane や最後の選択肢では、取り消しが単純な `up` にならない
- **押している間 `up` を繰り返す**: 動く回数が押していた時間で決まり、それは LED に出ない。あとから足せる
- **常に有効にする**: 長押しを使わない人も含め、全員が Select の遅れを負う
- **Approve の長押しで上へ**: 確定のつもりの押下が離すまで待たされ、ゆっくり押した確定がハイライトの移動になってしまう
