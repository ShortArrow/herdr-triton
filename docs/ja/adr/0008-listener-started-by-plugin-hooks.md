# 0008. herdr プラグインが bridge を起動し、することが無くなれば終了させる

- Status: Accepted
- Date: 2026-09-28

## Context

bridge はシリアルポートを開いてキーイベントを読み、herdr をポーリングする。
そのため、キーが意味を持つ間はずっと動いている必要がある。
一方、herdr のプラグインは v1 では常駐プロセスとして動かせず、startup とイベントフックのたびにプロセスを1つ起動する。
herdr はフックのプロセスにタイムアウトを設けず、終了させることもない。
`pane.agent_status_changed` のフックは、どの pane のイベントでも実行される（herdr `0d5d6f1`、`src/app/api/plugins/runtime.rs`、`PLUGIN_HOOK_EVENT_KINDS`）。

キーが意味を持つのは承認待ちのエージェントがいる間だけで、キューが空なら Jump・Approve・Select はどれも何もしない。
ホストが聞いていない間、firmware はキー入力を捨てる（`NoHost`）ので、押したキーがあとで実行されることはない。

## Decision

herdr のプラグインが、`startup` と `pane.agent_status_changed` で `bridge hook` を実行する。
デバイスのシリアルポートを開けたプロセスがリスナーになり、開けなかったプロセスは 500 ms 開き直しを試してから終了する。
リスナーは、キューが 5 秒続けて空になるか、herdr に 5 秒続けて届かなくなると終了する。
終了条件を持たない同じループを `bridge run` として残し、プラグインを使わないときに使う。

## Consequences

- 承認待ちが無い間はプロセスが動かず、リスナーの起動と終了は、ドキュメントに書かれたフックを通じて herdr が決める
- herdr が `HERDR_SOCKET_PATH` を渡すので、リスナーは起動されたセッションを受け持つ（ADR 0007）
- シリアルポートが排他的に開かれることが、多重起動を防ぐ鍵になる
- リスナーがポートを閉じる瞬間に新しい承認待ちが現れても、新しいフックの 500 ms の開き直しで拾える
- リスナーの出力を herdr のパイプに長く流さないよう、ログは `HERDR_PLUGIN_STATE_DIR` に書く

## Alternatives

- **手動か OS から起動する常駐の bridge**: プラグインが無くても動くが、常に動き続け、止めどきをユーザーに任せることになる。`bridge run` として残す
- **`[[startup]]` から起動して切り離す常駐の bridge**: herdr がフックの子プロセスを終了させないことに頼るが、プラグインのドキュメントはそれを約束していない
- **デバイスを HID キーボードにして herdr のキーバインドに割り当て、フックは1回で終わらせる**: リスナーは不要になるが、キー入力はフォーカスのあるウィンドウに入り、デバイスが単なる IO 機器でなくなる（ADR 0001）
