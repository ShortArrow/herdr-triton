# 0009. CDC-ACM 上で SCPI 風のテキストを使う

- Status: Accepted
- Date: 2026-09-28
- Supersedes: 0005

## Context

ADR 0005 では、postcard のメッセージを COBS で区切る方式を選んだ。
この通信は自前のデコーダでしか読めないので、デバイスを確かめるには、このリポジトリのツールをビルドして動かす必要がある。
デバイスは単なる IO 機器であり（ADR 0001）、この種の機器はシリアルターミナルから SCPI で操作するのが一般的である。

## Decision

ホストは SCPI 風のコマンドをテキストの行で送り、デバイスは問い合わせにだけ答える。
キーイベントはデバイスのキューに溜め、`KEY:EVENt?` で読み出す。
`protocol` crate は型付きのコマンドと返事を持ち続け、そのテキスト表現を加えるので、両端は引き続き1つの定義を共有する。

## Consequences

- どのシリアルターミナルからでも、このリポジトリのツールなしで、デバイスの識別、LED の設定、キーの読み出しができる
- デバイスは自分から何も送らないので、ターミナルには打ったコマンドへの返事だけが表示される
- キーイベントは送られてくるのではなく、20 ms ごとのポーリングで取りに行く。このポーリングがホストの生存通知も兼ねる
- firmware に小さなパーサとフォーマッタが載る。これは `protocol` を通じてホスト上でテストする
- postcard と COBS への依存が無くなる

## Alternatives

- **postcard と COBS を続ける（ADR 0005）**: コンパクトで既に動いているが、汎用のツールからは中身が読めない
- **キーイベントを、問い合わせ無しに行として送る**: 遅延は小さいが、返事と混ざり、SCPI 機器の振る舞いとも違う
