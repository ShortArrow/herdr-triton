# 0000. 記録は今有効な判断を書き、判断が変われば書き換える

[English](../../adr/0000-records-state-the-decision-in-force.md) | 日本語

- Status: Accepted
- Base: [`5d65935`](https://github.com/ShortArrow/herdr-triton/commit/5d65935e1803cf9c5ed68d50c5518b6e57e71089)

## Context

記録を読むのは、コードがなぜこうなっているかを知りたい人で、その理由が今も成り立つかを判断しなければならない人である。
成り立っている判断は、今の形で書かれていて初めて役に立つ。
あとの記録が前の記録の一部をそれぞれ変えていくと、今有効な判断は記録の連なりに散らばる。
読む人はすべてのリンクをたどり、変更を順に当てはめて組み立て直すことになる。
以前の文面とそれを書いた時期は、git がすでにすべて持っている。

## Decision

- 1つの記録は1つの判断で、最初に判断した順に番号を振る。番号は使い回さない
- 判断が変わったら、Status にかかわらず、その記録をその場で書き換え、今有効な判断を書く。置き換えられた設計は、やめた理由とともに `## Alternatives` に移す。変更がそれ自体で別の判断なら、新しい記録にする
- 本文は現在形で書く。`## Context` には、今ある力関係と、それらがどこで張り合うかを書く。`## Alternatives` には、それぞれの不採用を、理由が成り立つ間だけ有効なものとして書き、理由が無くなれば消す
- その時点でしか説明できない判断、つまり今は無い制約の下で下し、今有効な判断のどれにも関わらない判断は、記録にしない。その判断で決めたコミットのメッセージに書く
- 記録が参照するのは、自分が前提にしている記録だけとする。自分を前提にする記録は参照しないので、参照は輪にならない
- 判断がもう有効でなく、その話題を引き継ぐ記録も無い記録は `Withdrawn` にする。話題を別の記録が持つようになった記録も `Withdrawn` にし、それがどの記録かを書く。その記録の `## Alternatives` に、取り下げた設計を載せる
- 同じ番号の英語版と日本語版は同じことを書き、同じコミットで変える

### 見出し

```markdown
# NNNN. <判断を1文で>

[English](../../adr/NNNN-<slug>.md) | 日本語

- Status: Accepted
- Base: [`abc1234`](https://github.com/ShortArrow/herdr-triton/commit/<完全なハッシュ>)
```

| 項目 | 意味 |
|---|---|
| Status | `Draft`、`Accepted`、`Withdrawn` のどれか。`Draft` は `## Open questions` が空になったら `Accepted` にする |
| Base | 記録を最後に書いたコミットの親。GitHub のそのコミットへリンクするので、記録が話しているコードを1クリックで開ける |

日付は書かない。それぞれの版をいつ書いたかは git が持っている。
英語版も同じ見出しを持つ。項目名は英語のままで、2行目は `English | [日本語](../ja/adr/NNNN-<slug>.md)` とする。

### 本文

`## Context`、`## Decision`、`## Consequences`、`## Alternatives` をこの順に置く。
`Draft` は最後に `## Open questions` を足し、まだ決めることを1つずつ書く。`Accepted` にしたら外す。
`Withdrawn` の記録は、何を決めていたかと、今その話題を持つ記録を書いた段落1つだけにする。

## Consequences

- 1つの記録を読めば、今有効な判断が分かる。その経緯は、そのファイルの `git log -p` で見られる
- 判断を変えるときは、その記録と、その判断を書いているすべての文書を1つのコミットで直す
- 記録の Alternatives は、置き換えた設計の分だけ増えるので、何を試したかも分かる

## Alternatives

- **採用した記録は書き換えず、変更は前の記録を置き換える、または一部を変える新しい記録にする**: どの文面も書いたときのまま残るが、今有効な判断を記録の連なりから組み立てることになる。リンクの1つ1つが、前の記録の持つ逆向きの参照になる
- **判断を記録ではなく仕様に書く**: 読む場所は1つになるが、仕様はシステムが何をするかを書くもので、力関係ややめた設計がそれを埋めてしまう
