# 0001. キーボードは HID ではなくシリアルでホストのブリッジに繋ぐ

[English](../../adr/0001-serial-bridge-architecture.md) | 日本語

- Status: Accepted
- Date: 2026-09-28

## Context

3キーで herdr のエージェントを操作し、各キーの LED に herdr の状態を表示したい。LED の表示にはホストからデバイスへ情報を送る経路が必要になる。herdr の操作は Socket API（改行区切り JSON）で行える。

## Decision

デバイスは USB CDC シリアルでキーの押下・解放を送り、LED の指示を受け取るだけにする。ホスト側の常駐プロセス `bridge` が herdr の Socket API に接続し、状態の保持、キー入力から操作への変換、LED 表示の決定をすべて担う。

## Consequences

- どのウィンドウにフォーカスがあってもキーが誤入力にならない
- 振る舞いの変更は bridge だけで済み、ファームウェアの書き換えが少ない
- 振る舞いを bridge の純粋な状態遷移としてホスト上でテストできる
- bridge が動いていないとデバイスは何もしない

## Alternatives

- **HID キーボードとして F13〜F15 を送り、herdr のキーバインドで受ける**: LED へ状態を返す経路が別途必要になる。キー入力がフォーカス中のアプリに届くため、herdr 以外にフォーカスがあるときに効かないか、誤入力になる
- **判断をファームウェアに持たせる**: デバイスは herdr のソケットに直接触れないため、結局ホスト側の中継が要る。振る舞いを変えるたびに書き込みが必要になり、テストも実機に依存する
